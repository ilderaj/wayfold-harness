# Working with WayFold Harness

Describe the result you need. The enabled plugin can be selected by Codex when
its skill description matches the task; explicit skill selection is available
when needed. Automatic selection is contextual, not guaranteed.

For a quick question or small bounded change, work directly. For work needing
continuity, restore the original Task ID and three files. Record scope and
acceptance, act within the existing authorization, verify the actual outcome,
and save material decisions or recovery checkpoints. Do not create a parallel
tracker or restart a waiting task merely because a binding is missing.

Use installed professional skills only when relevant. WFH is author-neutral:
Matt and other sources can be selected. Respect explicit choices and invocation
policy, distinguish same-name sources, and report unavailable dependencies.
Do not install a missing package or route to another provider silently.

When delegating, give helpers bounded disjoint work; the main executor reviews
results and retains ownership of planning and acceptance. A helper reply alone
is not proof of completion. Office results need artifact checks; code changes
need relevant behavioral verification. External writes keep their real scope
and identity guards.

To stop WFH, disable its native plugin and use the Host's supported fresh-session
boundary. Independently installed user skills and saved task data remain.
No project enable command, adoption cron or global hook is needed for WFH.

Version 3 remains a candidate until the migration dossier records live
installation and behavior acceptance.
